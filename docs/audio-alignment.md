# 音频辅助对齐（0.3.0）

默认混合模式在原视觉序列算法上增加本地音频证据。适合画面打码或被遮挡而原声音仍保留的版本。它不依赖云端识别服务，不下载模型，也没有使用语音转写。

## 为什么音频对齐可能失败

本项目中没有找到用户之前失败的音频实现，因此无法确认当时原因。常见需要排查的方向是：选错配音音轨、把音频采样数直接当视频时间、丢失音轨起始 PTS、整集只求一个固定偏移、在静音或重复 BGM 上强行匹配，以及剪辑/变速造成的分段偏移变化。

例如源在中途删去一秒，删减前的时间偏移与删减后的时间偏移不同。一个全片偏移无法同时满足两段。

[Chromaprint 官方说明](https://github.com/acoustid/chromaprint) 将其定位为近乎相同的录音识别，明确不是通用指纹方案；完整文件身份相同也不等于每个片段已经对齐。[audfprint](https://github.com/dpwe/audfprint) 提供频谱地标、局部片段定位和一致时间偏移的参考。本次代码独立实现了适合本项目的局部匹配，不复制或调用 audfprint 的数据库。

## 当前流程

1. 列出音频流；优先选同语言音轨，支持显式指定源/目标音轨。未标语言时用首个音轨并在报告中说明；两边有明确但不相同的语言时，默认停用音频辅助。
2. 使用 FFmpeg 按实际 PTS 解码为单声道 11025 Hz PCM。`ashowinfo` 位于重采样和下混之后，帧 PTS 与实际消费的样本一一核对。时间戳跳变拆为独立区间，不跨越丢失的数据推算。
3. 在有能量的声音中提取短时频谱峰值和地标对，检索多个局部时间偏移；要求足够多不同指纹、足够时间跨度、偏移集中，且没有竞争强度接近的其他位置。
4. 对锚点当时及两侧的短时频谱再次复核。这个步骤用于阻止“借用了删除区间两侧的指纹，误配区间内部”。只依靠邻近指纹的初始版本曾在合成目标删减样例中出现边缘误配，增加此验证后该测试通过。
5. 每 0.5 秒尝试建立音频锚点，并生成单调的分段映射。静音、单音、重复声音和无法确认的位置保留未映射状态。
6. 混合模式将音频锚点和视觉结果交叉检查。明确的视觉编辑断点不由音频插值跨越；稳定的小幅音画偏差只在至少五个重叠位置、跨度至少三秒且离散度足够低时校准。无法解释的冲突在严格和宽松模式下都进入待复核区间。

该音频算法当前主要针对近乎相同的声音录制、重编码、音量变化与剪辑。它没有实现完整的变速/变调鲁棒匹配，也不能保证不同配音、重新混音和替换配乐的对应关系。[librosa 的 DTW 示例](https://librosa.org/doc/0.11.0/auto_examples/plot_music_sync.html) 展示了音乐速度变化的另一类处理，但不能直接视为本项目任意番剧的可靠映射证明。

## 运行与诊断

```bash
python -m bili_danmaku_mapper align   --source source.mp4 --target target.mp4 --danmaku raw.json --output mapped.json   --evidence-mode hybrid

# 指定目标第二条音频流：编号是音频流内序号
python -m bili_danmaku_mapper align   --source source.mp4 --target target.mkv --danmaku raw.json --output mapped.json   --evidence-mode hybrid --source-audio-stream 0 --target-audio-stream 1
```

`visual` 关闭音频，`audio` 用于单独检查声音匹配。`--algorithm legacy` 保留旧 AAP，不启用音频辅助。音频不可用时混合模式保持视觉结果，纯音频模式会明确报告缺少音轨等错误。`EVIDENCE_MODE`、`SOURCE_AUDIO_STREAM`、`TARGET_AUDIO_STREAM` 可配置在环境中。

报告仍使用 `schema_version: 1`，新增可选锚点 `evidence` 字段，旧报告可继续读取。逐条弹幕记录的是其实际锚点/插值端点的支持来源；音频诊断包含所选音轨、退回视觉原因、指纹与锚点数量、音画校准偏移和冲突数量。评分仍不是正确概率。

`--mode lenient` 不能绕过音画证据冲突；明确给出的人工锚点本身优先，周围未经确认的位置仍会保留复核。纯音频模式也不意味着声音时间已由画面校验；若媒体本身音画不同步，而没有可靠视觉结果供校准，需人工确认或指定锚点。

缓存键包含视频内容摘要、音轨和音频算法版本。PCM 暂存于任务专用临时目录，指纹完成后移除；长片不会在内存中保存整段频谱。音频可能增加解码、计算和临时磁盘开销，暂无真实整集性能验收。

## 本次验证

完整 Python 回归 **67 项通过**，其中新增 17 项音频测试。播放器逻辑测试、依赖诊断和包安装检查通过。

音频素材为确定性合成的多组变化频率信号，约 9–10 秒；两边分别使用 44100 / 48000 Hz 音频，以 AAC 96k 编码。统计分母保留全部测试弹幕，未映射结果不从分母中删除。

| 场景 | 可靠输出 / 全部 | 时间误差 P95（ms） |
|---|---:|---:|
| 头部删减 | 83/83 | 3.40 |
| 源中间删减 | 70/80 | 24.76 |
| 目标中间删减 | 75/90 | 21.68 |
| 音量降到 30% | 90/90 | 0.00 |
| 源静音两秒 | 65/90 | 0.00 |
| 非零容器起点 | 90/90 | 0.00 |
| 源画面全部遮黑 + 声音保留 | 80/80 | 3.40 |

所有已接受结果均在对应位置 200 ms 内；目标被删掉的区间未输出对应弹幕。画面全遮黑场景中，纯视觉输出 0/80，混合模式输出 80/80。这证明当前实现能够在受控例子中用声音补救完全失配的画面，不能推导真实番剧上的同等覆盖率。

另外验证了三百毫秒音轨延迟的视觉校准、重复片段的默认拒绝与人工锚点消歧、静音和纯音拒绝、不同声音拒绝、多音轨语言选择、显式音轨编号、缓存损坏恢复、无音频回退、音画冲突复核，以及不跨越视觉已知剪辑边界。
