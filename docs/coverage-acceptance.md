# 严格模式覆盖率恢复验收

**实验功能默认关闭。真实影片严格接受比例由 46.59% 提高至 81.99%；真实准确率尚未通过人工验收。**

## 同一影片的阶段结果

| 流程/阶段 | 可靠弹幕 | 严格接受比例 |
|---|---:|---:|
| 原默认流程 | 4535 / 9734 | 46.59% |
| 原音频优先流程 | 2286 / 9734 | 23.48% |
| 新候选上下文、精定位与共同融合 | 5340 / 9734 | 54.86% |
| 增加局部粗特征重检 | 5451 / 9734 | 56.00% |
| 增加实际帧补点 | 6583 / 9734 | 67.63% |
| 增加局部音频补证 | 7981 / 9734 | 81.99% |

均匀时间网格（每 0.5 秒取中点）覆盖率：46.72% → 82.82%。估算输出均为 0，严格插值仍不超过 1 秒。

整片实测使用 `visual_first` 实验流程；两种调度的锚点一致性在合成样例中验证，没有额外宣称真实整片音频优先计时结果。

这些是自动规则接受比例。新增接受 3551 条、撤回 105 条；共同接受 4430 条，其中 16 条时间变化超过 200 ms。共同结果时间差 P95 为 77.8 ms，只说明新旧一致程度，不能当作真实误差。

旧音频优先的整段屏蔽诊断影响 4153 条弹幕；新流程用序列支持与重新一致的证据确定冲突范围，不直接删除屏蔽。仅重放旧视觉点改进分段的预备试验为 45.81%，说明收益需要新的匹配证据；它不是本表单项消融。

局部音频补证新增了 1398 条可靠弹幕。通过长序列检查的音频候选大多来自邻居限定范围内的单声道重检（8750 个）；左右/中心声道变体共 81 个。候选包含原有位置，不能将候选数量当作新增弹幕数量。

## 失配归因

原默认流程剩余 5199 条：2554 条位于断点/未验证区间，2481 条段内证据间隔超过 1 秒（671 条对应约 1.04 秒），84 条首先被冲突屏蔽，80 条没有可靠起始片段。计数按首个拒绝原因归类；底层条件可能重叠，移除一条规则影响的数量不能直接当作可恢复量。

新版首轮全局视觉的 15086 个采样点分解：

| 首轮结果 | 帧数 |
|---|---:|
| low_information | 1843 |
| verified_visual_anchor | 8796 |
| no_hash_candidate | 2154 |
| appearance_rejected | 81 |
| candidate_ambiguity | 867 |
| path_conflict | 1131 |
| context_failed | 211 |
| precision_failed | 3 |

完整首轮候选与拒绝事件位于暖缓存运行报告的 `candidate_audit`；局部检验事件会重复，不等于唯一帧数。`no_hash_candidate` 指目标质量和时间约束筛选后没有合格哈希候选，不能全部归因于哈希阈值。

最终仍待复核 1753 条：952 条超过严格间隔，549 条位于断点/未验证区间，172 条音画证据冲突，80 条无可靠片段。尚不能将这些全部归因于真实删减。

## 时间、缓存与空间

| 使用情形 | 实测耗时 | FFmpeg 启动 |
|---|---:|---:|
| 复用已有及部分补点特征的整片实验 | 473.8 秒 | 1019 |
| 特征暖缓存重新求解 | 353.7 秒 | 0 |
| 复用对齐结果并重新映射弹幕 | 1.20 秒 | 0 |

首项不是空缓存首跑。第二项因音频锚点缓存键补全参数，首次从已有指纹重建锚点；没有重新解码。三次输出的播放器 JSON 完全一致。

原默认暖缓存 137.8 秒来自此前记录，增加补证的代价是更多计算；没有将不同缓存条件的记录描述为配对提速实验。本轮优先覆盖，不宣称该模式比默认匹配更快。

本次新增视频解码 634 次，全部为参考片的局部 4 fps 补点；目标 4K 视频特征可用，没有新增目标视频解码。另有 385 次短窗口音频解码。所有使用软件路径，没有制作原片播放/转码副本。实际磁盘 I/O 未测量。

实验逻辑空间采样峰值 3.29 GiB，低于 4 GiB；包含重复硬链接和 pytest 临时数据。已清理本实验结束的测试临时目录，没有清理用户影片、生产缓存或旧任务结果。最大新生成视频 1.61 MiB，为合成验收素材。

进程树峰值 RSS 受沙箱限制未采集；机器指标保留此限制，并记录重复运行的主进程峰值，不能混称进程树内存。

## 准确性与回归

- 合成验收：21 个场景 × 两种调度，42 次运行；错误接受 0，最差场景 P95 37.15 ms。完全重复的片段要求拒绝。
- 包括删除、插入、帧率/VFR、速度差、打码、静音、重复内容、音画延迟、采样相位、长静止、目标中心声道、源中心声道与混音叠加 PAL 等场景；两种调度的接受锚点完全一致。
- Python 回归：200 passed, 1 warning in 51.46s；另 1 项验收门槛测试通过，共验证 201 项。前端 4 组测试通过。
- 独立浏览器合成验收：开关默认未选；启用后按任务持久化；完成任务明确显示实验提示；完成不自动跳播放器；独立测试服务已退出。没有访问 B站账户或操纵生产任务。

## 真实影片复核与默认启用门槛

全部 105 条撤回、16 条大于 200 ms 的变化，加上新增接受、共同接受、仍未映射的分层抽样，均进入复核清单。额外保留 30 个均匀时间点和所有新分段/冲突边界。标注字段默认空，不把预测当真值；discovery 与 validation 分组分别用于分析和验收。

交互复核页面、机器复核清单、实验弹幕和原始机器指标仅保存在本地私有归档，不随仓库发布。原始指标含本机路径及逐位置诊断；本页保留脱敏后的汇总结果，真实影片截图不公开。

人工标注完成前不宣称真实准确率达到 99%，不将新流程设为默认。最终确认需检查新增接受以及共同结果，验证无新增确定性错误、P95 不超过 200 ms、无时间倒退和跨删减吸附；未通过的模块继续保持实验状态。

## 发布边界与可重复性

代码在独立副本开发，输入视频和原始弹幕的设备号、inode、大小、纳秒时间保持一致；没有操作生产任务或重启现有服务。新结果另存，不替换历史成品。

整片计时源码冻结于 `run-code-v3`，重复/最终缓存验证源码为 `run-code-v4`；后续补全缓存键和诊断，并增加该立体声参考输入未涉及的源中心声道分支。源码摘要、回归证据和限制均在机器指标中保留。没有把不同版本记录伪装成同一计时版本。
