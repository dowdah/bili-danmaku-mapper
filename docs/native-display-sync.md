# 原生弹幕显示同步修复（0.11.2）

## 原因与上一轮验收缺项

0.11.1 已生效，但只改善了 Lua 提交时钟。真实电影播放时测得脚本约 58 次／秒提交，原 `video-sync=audio` 模式的 OSD 绘制仍约 24 次／秒。原先小尺寸合成片的 60 次／秒是提交率，不是实际显示流畅度；不能用它认定本片已流畅。

mpv 0.38 的正常播放循环会让 OSD 随视频显示自然重绘。参考 [playloop.c 的 handle_osd_redraw](https://github.com/mpv-player/mpv/blob/v0.38.0/player/playloop.c#L604)。

## 修复

本工具创建的 IINA 会话改用 `video-sync=display-vdrop`；工作台重连已保活会话时同样应用。该模式让显示按刷新节奏重复或丢弃视频显示帧，以音频时钟保持同步。没有使用 `display-resample`、视频插帧滤镜或编码器，不调整原音频速度，不修改 IINA 全局偏好。

参考 [mpv 0.38 显示同步实现](https://github.com/mpv-player/mpv/blob/v0.38.0/player/video.c#L753)：该模式的视频／音频速度校正系数为 1，音画同步通过视频显示的重复或丢弃补偿。

保留独立弹幕 OSD、原始外挂 ASS、颜色、字号及各自偏移。接口新增只读 `render_sync` 状态；网页区分已配置待播放、已启用，以及无法启用时的提示，避免将设置值冒充生效状态或实际帧率。

## 本片真实大窗口对照

原 MKV、同一位置附近约五秒窗口、3440×1934 的 IINA 显示区域，音轨为 DTS-HD MA 5.1(side)，外部中文 ASS 原样选中，复用 7,981 条弹幕。新旧模式交替各三轮，每轮预热约一秒、测量约四秒；静音进行，结束后恢复测试前位置与静音状态并暂停。没有截图、影片副本或新对齐。

采用 mpv 渲染函数 `pass 'drawing osd'` 的逐次 trace 日志计数；它来自真实渲染调用，而非 Lua 的 overlay:update 次数。原始 GPU 耗时环形样本会漏采，不具备逐帧计数语义，已弃用 `real-comparison.json` 中由它推导的绘制率；正确记录为 `real-render-comparison.json`。相关实现见 [GPU video.c](https://github.com/mpv-player/mpv/blob/v0.38.0/video/out/gpu/video.c#L3166)。

| 指标（三轮） | 0.11.1 的 audio 模式 | 修复后的 display-vdrop |
| --- | ---: | ---: |
| OSD 渲染调用率中位 | 24.00 次／秒 | 59.99 次／秒 |
| 绘制间隔 P95 | 约 45 ms | 约 19–20 ms |
| 新增视频／解码丢帧 | 0／0 | 0／0 |
| 音频速度校正 | 1.0 | 1.0 |
| 视频速度校正 | 1.0 | 1.0 |
| 最大采样音画误差 | 0.54 ms | 9.03 ms |

两组均直接解码 DTS-HD MA 为六声道，当前设备输出双声道 PCM；原始外部 ASS 保持选中，没有应用层 AAC 重编码或音频重采样模式。显示同步模式没有开启视频插帧，原始视频仍为 24 fps。

以上验证到实际渲染调用和同步状态，**仍不是物理显示屏高速摄影验收，也不代表全片所有负载或设备都能维持相同表现**。端到端主观流畅度、长期观看及物理 5.1 仍需正常使用确认。短对照中没有 CPU 和内存的受控长期统计，不给出该项改善承诺。

## 回归与更新

完整 Python 与前端回归、已保活会话重连、原始字幕及进度所有权测试通过后发布；测试日志保存在本地私有实验归档，不随仓库发布。更新前备份源码和 SQLite，沿用当前端口，重连本工具的 IINA 会话，恢复原位置并保持暂停，不改动用户影片、字幕、原始弹幕及映射结果。
